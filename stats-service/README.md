# Private statistics query service

The static app cannot execute server-side SQL. This service separates compact statistics records from full profiles and game logs. The Python loopback preview and Cloudflare D1 deployment use the same SQLite schema and query semantics. No paid service or hosting account has been enabled.

`catalogue.py` builds a new projection without changing source data. Rows are keyed by verified person, competition and explicit season. Unknown seasons and roster-only records do not enter rankings. Qualification stays competition/season specific. Exact totals and source ratios are preserved; rounded averages are not multiplied into totals. Source statistics never contain scouting notes or ratings.

`serve.py PRIVATE_DATABASE --port 8778` starts a loopback-only preview, with Host checks and no access to service files. `stats-preview.html` loads just filter metadata and the first 50 rows. Query parameters combine OR inside each filter and AND between filters. Sorts cover the full matching result set, with a stable ID tie-breaker and NULL values last. The UI has an abortable 300ms search debounce, 25/50/100 pagination, versioned in-memory caching and explicit season switching.

For hosting, `worker.mjs` verifies the DragonsHub Firebase token's RS256 signature, issuer, audience and expiry, then checks the existing owner's active administrator role. The D1 database is inaccessible without that authorization. Only DragonsHub and EuroScout origins are permitted. Cached results are keyed by user and dataset version; role checks expire in 60 seconds. No API keys or passwords are needed in this code.

Before deployment: create the free Workers/D1 account, replace the example binding ID, import the private SQLite SQL export into D1 and deploy the Worker. Keep private SQL, SQLite databases and real player projections outside Git. Set the application's query endpoint to the verified Worker origin. Initial service/data setup is still pending; do not claim that static Pages provides server queries.

`euroscout-stats-integration.js` activates only after `EUROSCOUT_CONFIG.statsEndpoint` is configured. Until then the existing production Stats screen continues to work. The integrated `?stats=1` entry verifies access and queries the first page without fetching the complete catalogue or game logs. Existing Compare, Charts and Fit Finder renderers receive the selected competition/season records only when requested. Full profile/scouting data loads through the existing protected workspace on the first profile request; that first request still incurs the existing catalogue load. Closing the profile returns to the selected Stats filters.

Local acceptance: 10 data/query checks plus incremental refresh/failure preservation, signed-token authorization/rejection/cache checks, existing cloud-save/snapshot-isolation/private-fixture checks, and a routed browser integration check covering multi-filter queries, all three tools, native profile/return, desktop/iPad/phone and both themes. The full-size projection contains 19,106 statistical records across explicit 2026/27, 2025/26 and calendar 2026 seasons. Latest representative local SQL queries measured 9–86 ms; the latest routed local initial Stats table measured 0.462 seconds. An earlier cold run measured 3.188 seconds. These figures exclude production network latency and do not establish hosted performance. The 40.6 MB SQL export was replayed locally with matching counts; estimated indexed writes are 85,866. No hosted deployment or hosted acceptance claim has been made.

Some Swiss source metrics cover fewer games than the appearance count. Preserve each published average and its metric coverage, mark smaller samples with a dagger, and withhold derived rates that would combine incompatible samples. Historical game-log totals are used only when all appearances and all values for that metric are present; unknown values do not become zero.

Hosting checks follow the [D1 limits](https://developers.cloudflare.com/d1/platform/limits/) and [import rules](https://developers.cloudflare.com/d1/best-practices/import-export-data/). Multi-select values use bounded JSON parameters, avoiding D1's 100-parameter limit. Search uses normalized `instr`, avoiding its 50-byte LIKE-pattern limit. SQL imports omit transaction wrappers and split large metadata statements below 100 KB. Two selective secondary indexes plus the row identity index keep the tested initial import below the free daily write allowance; verify actual D1 import usage before advancing the published baseline. No paid tier is enabled automatically.

`prepare.py --source PRIVATE_PROJECTION.json --countries COUNTRIES.json --out PRIVATE.sqlite --sql` creates an atomic local projection and compatible initial SQL outside the public repository. `delta.py LAST_PUBLISHED.sqlite NEW.sqlite PRIVATE.delta.sql` emits only changed records, ignoring timestamps when values are unchanged. A disappeared row stops the export by default; use `--allow-removals` only after validating a correction. Import into a staging database, verify query counts/version and authorization, then change the Worker binding. Advance the private published baseline only after successful verification. Keep the previous binding/data available on failures.
