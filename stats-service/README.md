# Private statistics query service

This service separates compact statistics records from full profiles and game logs. The Python loopback preview and Cloudflare D1 deployment use the same SQLite schema and query semantics. The hosted service uses the free Workers/D1 plan; publication never enables a paid plan.

`catalogue.py` builds a new projection without changing source data. Rows are keyed by verified person, competition and explicit season. Unknown seasons and roster-only records do not enter rankings. Qualification stays competition/season specific. Exact totals and source ratios are preserved; rounded averages are not multiplied into totals. Source statistics never contain scouting notes or ratings.

`serve.py PRIVATE_DATABASE --port 8778` starts a loopback-only preview, with Host checks and no access to service files. `stats-preview.html` loads just filter metadata and the first 50 rows. Query parameters combine OR inside each filter and AND between filters. Sorts cover the full matching result set, with a stable ID tie-breaker and NULL values last. The UI has an abortable 300ms search debounce, 25/50/100 pagination, versioned in-memory caching and explicit season switching.

For hosting, `worker.mjs` verifies the DragonsHub Firebase token's RS256 signature, issuer, audience and expiry, then checks the existing owner's active administrator role. The D1 database is inaccessible without that authorization. Only DragonsHub and EuroScout origins are permitted. Cached results are keyed by user and dataset version; role checks expire in 60 seconds. No API keys or passwords are needed in this code.

For a new deployment, replace the example binding ID, import the private SQLite SQL export into D1 and deploy the Worker. Keep the real binding file, private SQL, SQLite databases and player projections outside Git. The configured application endpoint is an authenticated Worker; static Pages serves the interface only.

`euroscout-stats-integration.js` activates only after `EUROSCOUT_CONFIG.statsEndpoint` is configured. Until then the existing production Stats screen continues to work. The integrated `?stats=1` entry verifies access and queries the first page without fetching the complete catalogue or game logs. Existing Compare, Charts and Fit Finder renderers receive the selected competition/season records only when requested. Full profile/scouting data loads through the existing protected workspace on the first profile request; that first request still incurs the existing catalogue load. Closing the profile returns to the selected Stats filters.

Local acceptance includes 15 data/query/refresh checks, source-identity stability, signed-token authorization/rejection/cache checks, existing cloud-save/snapshot-isolation/private-fixture checks, and routed browser integration covering multi-filter queries, all three tools, native profile/return, desktop/iPad/phone and both themes. The initial private hosted import contained 19,106 records and used 85,877 indexed writes. Consolidating 683 verified statistical aliases reduced the hosted count to 18,423 without deleting any player profile or notes. Full optional-pack hydration additionally finds 6,659 historical records. The refresh publishes current corrections first if necessary and labels queued historical additions in the interface until the free allowance permits them. Local timing measurements do not establish production network performance.

Some Swiss source metrics cover fewer games than the appearance count. Preserve each published average and its metric coverage, mark smaller samples with a dagger, and withhold derived rates that would combine incompatible samples. Historical game-log totals are used only when all appearances and all values for that metric are present; unknown values do not become zero.

Hosting checks follow the [D1 limits](https://developers.cloudflare.com/d1/platform/limits/) and [import rules](https://developers.cloudflare.com/d1/best-practices/import-export-data/). Multi-select values use bounded JSON parameters, avoiding D1's 100-parameter limit. Search uses normalized `instr`, avoiding its 50-byte LIKE-pattern limit. SQL imports omit transaction wrappers and split large metadata statements below 100 KB. Two selective secondary indexes plus the row identity index keep the tested initial import below the free daily write allowance; verify actual D1 import usage before advancing the published baseline. No paid tier is enabled automatically.

`prepare.py --source PRIVATE_PROJECTION.json --countries COUNTRIES.json --out PRIVATE.sqlite --sql` creates an atomic local projection and compatible initial SQL outside the public repository. `delta.py LAST_PUBLISHED.sqlite NEW.sqlite PRIVATE.delta.sql` emits only changed records, ignoring timestamps when values are unchanged. A disappeared row stops the export by default; use `--allow-removals` only after validating a correction. Initial imports use a staging binding. Subsequent delta imports verify the expected remote version before transmission and verify the resulting count/version before advancing the private published baseline.

`project.cjs PRIVATE_SETTINGS.json` runs the existing native loader and optional league packs in an isolated browser with external traffic blocked. It whitelists source biographies, statistics and verified source links, excluding notes, ratings, raw logs and credentials. Canonical source identity is retained across loader order changes; conflicting birth years remain separate. The source projection does not ingest private manual profile overrides; the native player profile remains authoritative for those edits.

`sync.py --settings PRIVATE_SETTINGS.json` connects that projection to a bounded delta refresh. Settings and the published baseline are private. DragonsData invokes it after local collection when its private `stats-query.json` exists. A UTC-day ledger reserves estimated indexed writes before importing, reconciles actual writes on success and conservatively retains reservations after interruptions. New historical additions may be deferred without removing any published row or current-season addition. If current corrections cannot fit either, the complete import is deferred. No background cloud collector or paid subscription is enabled: the next DragonsData Refresh retries pending history. Snapshot failures retain the last good baseline and do not fail the underlying source collection.

When a native-verified person group contains older link aliases, `stable_person_ids` retains an existing statistics identity within that competition/season. The canonical group is established by native source links, never by matching names in the projection. This removes duplicate aliases without renumbering unrelated historical records. A planned identity correction still requires a reviewed delta: normal refreshes stop unexpected disappearing rows.
